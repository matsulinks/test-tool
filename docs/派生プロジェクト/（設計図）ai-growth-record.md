# AI育成記録システム / AI Growth Record System

## 0. 出自 / Origin

> **これは「融合（Convergence）」によって生まれたプロジェクトである。**
>
> - 親A：**ATP 進化ループ**（Grokが改善提案を自律的に生成する）
> - 親B：**派生プロジェクト促進FW**（種を記録し、家系図を管理する）
> - 融合のきっかけ：「進化ループが提案し、その結果が家系図に刻まれていく仕組みを合わせたらどうなるか？」
> - 何が新しいか：**AIが自分の成長の歴史を、自分で書き記す。**

---

## 1. 哲学 / Philosophy

**「自己進化が止まらないシステムは、最初から『自己進化するように設計』されている。」**

多くのシステムは「使われるたびにうまくなる」とは言うが、実際には人間が手動で改善する。本システムの哲学はそこが違う。**AIが提案し、AIが実装し、AIがその結果を記録し、その記録を次の提案のインプットにする。** 人間は「方向性を承認すること」だけをやる。

---

## 2. Concept (比喩を用いた説明)

**「自分で日記を書きながら、昨日の日記を読んで今日の行動を決める人」**

普通の日記は記録だけ。しかしこのシステムは、過去の日記を読んで「昨日はここが良くなかった、今日はこうしよう」と自律的に判断し、行動し、また日記を書く。人間が読まなくても、AIが読む。AIが読むから、記録が次の改善につながる。

---

## 3. 中核の仕組み（自己進化ループ）

```text
┌─────────────────────────────────────────────────────┐
│                  自己進化の永久機関                    │
│                                                     │
│  [1] Grok が「現在のコード」と「過去の採用記録」を読む   │
│         ↓                                           │
│  [2] 過去に却下された提案は避け、採用された改善に       │
│      沿った「次の一手」を提案する（学習している）        │
│         ↓                                           │
│  [3] 開発AIが実装 → テスト全合格確認 → Issue Close    │
│         ↓                                           │
│  [4] ATPが結果を evolution-log.md に自動追記          │
│         ↓                                           │
│  [5] 次の [1] で、Grokは [4] の記録も読む            │
│         ↓                                           │
│         → [1] に戻る（永遠に）                        │
└─────────────────────────────────────────────────────┘
```

**このループが最初から組み込まれていれば、システムは放置されるほど賢くなる。**

## 4. 主要機能 (Main Features)

### 4.1. コンテキスト付き提案（Context-Aware Proposal）

進化ループの改善提案エンジンに「過去の採用記録を読む」機能を追加する。

Grokに渡すプロンプト（改善提案リクエスト）に以下を含める：

```text
これまでに採用された改善：
- execSyncのタイムアウト追加（G1、採用）
- REPO_NAMEの環境変数化（G1、採用）
- SQLite移行（G1、保留中）

これまでに却下された改善：
- （なし）

上記を踏まえた上で、次の一手を提案してください。
同じ提案を繰り返さないこと。保留中の提案は別角度で掘り下げても良い。
```

これにより、Grokは「同じ提案を繰り返す無限ループ」に陥らず、累積的に成長する提案を生成できる。

### 4.2. 世代ごとのスナップショット（Generation Snapshot）

進化ループの1サイクル（提案→実装→Close）が完了するたびに、そのときのコードの状態を記録する。

```text
docs/派生プロジェクト/
└── growth-record/
    ├── G1/               ← 第1世代のスナップショット
    │   ├── summary.md    ← その世代で何が変わったか
    │   └── metrics.json  ← 重複コード率 / ESLintエラー数 など
    ├── G2/
    └── ...
```

**ビジュアル化**: `metrics.json` を並べると、AIが生まれてからどれだけ賢くなったかが数字で見える。

### 4.3. 「最初から組み込む」ための初期設計（Zero-Day Integration）

このシステムの真価は「**後から追加した**」ではなく「**最初からある**」にある。

新しいプロジェクトの `setup.sh` の中に、進化ループの初期設定（Grok APIキー・採用記録ファイルの生成）を最初から含めておく。

```bash
# setup.sh の末尾に追加するだけで、自己進化が始まる
echo "🧬 [Final] 自己進化ループを初期化します..."
mkdir -p docs/派生プロジェクト/growth-record/G0
echo '{"duplicate_lines": null, "eslint_errors": null, "note": "初期状態"}' \
  > docs/派生プロジェクト/growth-record/G0/metrics.json
echo "✅ G0（初期世代）を記録しました。あとはAIが育てます。"
```

**効果**: セットアップが完了した時点で、すでにG0（ゼロ世代）が記録されており、初回の進化ループが動いた瞬間にG1が生まれる準備が整っている。
