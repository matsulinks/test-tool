# 🤖 開発AI（Claude）からのレビュー結果

ATPのコードベース（test-tool）に対する、開発AIからのレビューとリファクタリング提案のまとめです。
全体として「障害検知→Issue投稿→エスカレーション」のコンセプトは評価されていますが、本番運用に向けて信頼性と保守性（コピペ排除）を上げるための指摘が含まれています。

---

## 🚨 1. クリティカル（即対応が必要な問題）

1. **GitHub APIのRate Limit問題** (`github-connector.js`)
   - 現状: 30秒ごとの無制限ポーリング。未認証の場合60回/時でブロックされる危険あり。
   - **対策:** バックオフ（徐々に間隔を広げる）の実装。
2. **テストハング時の永遠待機** (`monitor.js`)
   - 現状: `execSync` にタイムアウトが設定されていないため、テストがハングするとATPごと止まる。
   - **対策:** `execSync(..., { timeout: 300000 })` （5分など）を追加。
3. **失敗カウンターの競合状態** (`safety-guard.js`)
   - 現状: ファイルロックなしでカウンターを読み書き（`fs.readFileSync` -> `fs.writeFileSync`）。並行実行時に壊れる。
   - **対策:** `fs.writeFileSync` の工夫、またはSQLite等を使う（シンプルにやるならアトミック書き込み）。
4. **報告書の削除検知漏れ** (`report-writer.js`)
   - 現状: インターバル（10秒おき）のポーリング。タイミングによっては削除を見逃すリスク。
   - **対策:** `fs.watch()` に置き換えてイベント駆動にする。

---

## 🧹 2. コードの重複排除・共通化（コピペ地獄の解消）

現在、各機能を作るために「同じような処理」があちこちにコピペで配置されています。
以下の `lib/` フォルダ配下に共通モジュールを作ることで、コード量を劇的に減らし、変更に強い設計になります。

| 現状の問題点 | 解決策（新設する共通ファイル） |
| :--- | :--- |
| HTTPSリクエスト処理が複数ファイルに重複 | **`lib/http-client.js`** <br> 煩雑な `https.request` のボイラープレートを一本化。 |
| インターバルループ（ポーリング待機）が重複 | **`lib/poll-until.js`** <br> `setInterval` を使って「条件を満たすまで待つ」処理を共通化。 |
| `console.log` の絵文字やトーンがバラバラ | **`lib/logger.js`** <br> `log.info()`, `log.fail()`, `log.warn()` 等に統一し、パースしやすくする。 |
| `fs.readFileSync` の `try-catch` が重複 | **`lib/safe-file.js`** <br> ファイルを安全に読み書き・削除する処理をまとめる。 |
| `.env` の読み込みや設定値が散在している | **`lib/config.js`** <br> `requireEnv` などで環境変数のチェックや、パスの設定を一元管理する。 |

## ⚙️ 3. 高優先度（運用上の細かな不備 / セキュリティ）

- **ハードコードの排除**: リポジトリ名（`matsulinks/vault-alchemist`）や `MAX_RETRIES (3)` を環境変数または `config.js` に追い出す。
- **ネットワークタイムアウト**: API呼び出し時に `req.setTimeout(10000)` 等がないため、通信不良でハングする。
- **プロセスクリーンアップ**: `obsidian-launcher.js` でクラッシュ時にVaultディレクトリが残る問題（`process.on('exit', cleanup)` を追加）。
- **クロスプラットフォーム非対応**: ObsidianのパスがMac専用になっている（OS判定が必要）。
- **セキュリティの穴**: 
  - `fs.rmSync(..., { force: true })` が任意ディレクトリを消せるリスク。
  - GitHubトークンがメモリに残り続ける問題。

## 🎯 次のアクション（Quick Wins: すぐやるべきこと）

どれから手を付けるか、以下の順番が効果的です：

1. **`lib/config.js` と `lib/logger.js` の新設**（一番散らかっている設定値とログを統一）
2. **`execSync` へのタイムアウト追加**（1行直すだけでハングを防げる）
3. **`lib/safe-file.js` と `lib/http-client.js` の新設**（通信とファイルのtry-catch地獄を消す）
4. **ポーリングを `fs.watch()` に置き換え**（検知漏れを撲滅）
